# OpsTerm v0.1.6

Portable Linux distribution and more selective close confirmation. Includes the terminal input/mouse/theme improvements from v0.1.5 and the existing egui interface.

## Linux packages

Both x86_64 and ARM64/aarch64 have a signed native executable, AppImage and portable tar.gz. The release baseline is glibc 2.35 (Ubuntu 22.04), covering modern Ubuntu/Debian, Fedora, Arch and CachyOS with a working display/graphics stack. musl/Alpine, 32-bit and older glibc are outside this baseline.

AppImage can run with `--appimage-extract-and-run` without FUSE. Its in-app updater downloads a separately signed image and atomically replaces the outer image file, keeping a rollback backup. Raw executables keep their existing update channel. Architecture/format, hash, URL and size remain bound to Ed25519 signatures.

The archive includes an atomic per-user installer (`./install.sh`, or `--prefix /absolute/prefix`), desktop/icons, a diagnostics helper and third-party license/source notices. Default installation retains `~/.local/bin/opsterm-egui`, including existing GNS3 command settings. OpenSSH, curl and graphics drivers remain host tools.

`OPSTERM_DISPLAY_BACKEND=x11` or `=wayland` chooses an explicit display backend for troubleshooting; `auto` remains the default. It does not change the environment inherited by terminal programs.

## Confirm only active/risky closes

- Connected SSH/Telnet/serial sessions and detected local foreground/background jobs require confirmation.
- Idle local prompts, disconnected tabs and opening placeholders close immediately.
- Window close and restart ask only if risky sessions remain; Cancel/Escape and focus restoration are preserved.
- Ordinary shell builtin `read`/loops are treated conservatively. Unknown/canonical editing states ask; prompt-like editor builtins such as `read -e` cannot always be distinguished without shell integration.

The reported CachyOS bug had no specific error or steps yet; broader packaging compatibility and tested startup do not claim to diagnose every desktop/GPU-specific issue.

D-Bus client library is statically linked under AFL-2.1. Full notices, license and the exact source archive are listed in [THIRD_PARTY_NOTICES.txt](https://github.com/Setiyoaryo/ops-term/blob/main/packaging/linux/THIRD_PARTY_NOTICES.txt).
