# OpsTerm v0.1.19

Portable macOS and Windows builds, plus the Linux release you already had.

## macOS

- New **aarch64 (Apple silicon)** and **x86_64 (Intel)** portable builds.
- The zip contains `OpsTerm.app`; the raw Mach-O binary is the signed update
  asset used by **Help → Check for updates**.
- Uses the macOS Keychain for saved credentials and vault resume.
- Command shortcuts, Option-as-Meta and the macOS-style menu already present in
  the egui client are unchanged.
- Serial consoles and OpenSSH askpass work; the build is **not notarized** yet,
  so Gatekeeper may ask for confirmation on first launch.

## Windows

- New **x86_64** portable build (`opsterm-egui.exe` plus a `.zip`).
- Uses Windows Credential Manager for saved credentials and vault resume.
- Local sessions start `%COMSPEC%`; OpenSSH sessions use the built-in
  `C:\Windows\System32\OpenSSH` client when present.
- The updater renames the running image aside before replacing it and restarts
  the new build. Serial consoles are not available on Windows.
- The build is **not code-signed** yet, so SmartScreen may warn about an
  unknown publisher.

## Release engineering

- `scripts/package_platform.py` assembles the portable artifacts and
  `scripts/release_layout.py` defines asset keys and filenames.
- The publish job signs macOS and Windows assets on Linux (`merge_release`) so
  every platform shares one manifest and one update key.
- The Linux AppImage/archive pipeline, distro compatibility matrix and smoke
  tests are unchanged.

Verification: 171 egui tests, 74 core tests, clippy for Linux and Windows, and
`cargo check`/`clippy --all-targets` for the `x86_64-pc-windows-gnu` target.
macOS compilation is exercised by the macOS release runners.
