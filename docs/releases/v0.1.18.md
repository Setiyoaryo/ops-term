# OpsTerm v0.1.18

Fix the recurring GNOME “OpsTerm is not responding” dialog on Wayland.

## Freeze fix

- Root cause: with vsync enabled (swap interval 1), Mesa's Wayland EGL
  `eglSwapBuffers` blocked the UI thread in `poll()` until the compositor sent
  a frame callback. GNOME withholds frame callbacks for hidden or occluded
  windows, so the UI thread could not answer the compositor ping.
- Evidence: every v0.1.17 stall report recorded
  `stage=native-event-loop-or-render main_wait=poll_schedule_timeout
  main_syscall=7` (poll), outside application UI code.
- vsync is now disabled. Repaints were already demand-driven and capped by
  `request_repaint_after`, so rendering cost is unchanged.

Verification: 171 egui tests and 74 core tests pass, including a regression
test that keeps vsync disabled. The release binary launched cleanly on a GNOME
Wayland session.
