# OpsTerm v0.1.10

Fix saved Telnet login and prevent pager commands from being sent before authentication on Huawei switches.

- Replace the fixed 1.5-second pager timer with a per-session queue waiting for configured credential answers, the corresponding processed terminal output, and a complete live vendor CLI prompt. Huawei retains `screen-length 0 temporary`; the Cisco command is not substituted.
- Normalize colored, fragmented UTF-8/ANSI login prompts and spaces before the colon. Password-only login is supported; password-change prompts and repeated authentication attempts are not filled automatically.
- Empty saved usernames can fall back to the selected credential's username. Repeated/double device clicks reuse the opening connection.
- Pager setup is one-shot, serialized after startup scripts, and canceled on disconnect, invalid/failed scripts or a 60-second readiness timeout. Scrolled history and stale pre-authentication banners cannot release the queued command.

Verification uses real loopback Telnet and the native GUI with an isolated D-Bus/Secret Service and synthetic credentials. It covers slow fragmented prompts, a prompt-shaped pre-auth banner, double click, exact username/password/pager order and keyboard roundtrip; it is not a claim of testing every Huawei model on physical hardware. The existing egui appearance and signed Linux updates are retained.

Dependency audit also reports existing, unchanged SSH/crypto advisories. They are documented in the [verification report](https://github.com/Setiyoaryo/ops-term/blob/main/docs/telnet-startup-2026-10-29.md); this release does not claim a clean dependency audit or a fix for the separately reported random freeze.
